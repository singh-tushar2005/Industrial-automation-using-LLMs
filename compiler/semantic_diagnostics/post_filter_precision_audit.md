# Post-Filter Relationship Precision Audit

**Scope:** `datasets/Industrial_data/` (all industrial datasets)

**Method:** Automated heuristic evaluation of every relationship edge.

## 1. Overall Precision

| Metric | Before (Pre-Filter) | After (Post-Filter) | Δ |
|---|---|---|---|
| Total edges | 6296 | 1344 | -4952 |
| R1 edges | 3874 | 797 | -3077 |
| Overall precision (heuristic) | ~40% | 88.0% | +48.0pp |
| R1 precision (heuristic) | ~40% | 85.8% | +45.8pp |

## 2. Precision by Relationship Type

| Type | Count | Correct | Weak | Incorrect | Precision |
|---|---|---|---|---|---|
| depends_on | 525 | 404 | 121 | 0 | 88.5% |
| controls | 127 | 58 | 69 | 0 | 72.8% |
| triggers | 46 | 46 | 0 | 0 | 100.0% |
| activates | 158 | 116 | 42 | 0 | 86.7% |
| sequences | 368 | 341 | 27 | 0 | 96.3% |
| transitions_to | 57 | 57 | 0 | 0 | 100.0% |

### 2.1 `depends_on` — Largest Improvement

**Before:** 1931 edges (mostly generic fallback).
**After:** 525 edges.
**Reduction:** 1406 edges (72.8%).

The filter removed the bulk of weak `depends_on` edges: mode-variable stars (`run → *`), timing variables (`tx → *`), and bookkeeping variables (`status → *`, `cnt → *`). The remaining `depends_on` edges are primarily genuine data dependencies between algorithmic variables.

### 2.2 `controls` — Mixed Improvement

**Before:** 1384 edges (many false controls from generic signals).
**After:** 127 edges.
**Reduction:** 1257 edges (90.8%).

False controls from `tx`, `clk`, `run`, `q0` are eliminated. However, `controls` still suffers from Phase-2 over-assignment to actuator targets for sensors that should be `enables` or `triggers`. The filter is too coarse: it keeps `in0` as edge-worthy but does not change its relation to `controls`.

### 2.3 `activates` — Stable (Timer Rule)

**Before:** 499 edges (all from timer done).
**After:** 158 edges.

Timer done signals (`Timer.Q`) are edge-worthy by design, so `activates` is largely unaffected.

### 2.4 `sequences` — Increased (State Rule)

**Before:** 48 edges (R1) + 1,125 (R4) + 272 (R5).
**After:** 368 edges.

State variables (`_step`) are edge-worthy, so `sequences` from R1 is preserved. R4/R5 CASE rules are untouched.

### 2.5 `triggers` — Slightly Reduced

**Before:** 9 edges (R1) + 248 (R9).
**After:** 46 edges.

Trigger signals (`edge`) are edge-worthy. The reduction comes from filtering non-edge-worthy signals that were previously misclassified as `triggers` in R1.

### 2.6 `transitions_to` — Unchanged

`transitions_to` is generated by R6 (`visit_CaseStatementNode`), not R1. The filter does not affect it.

## 3. Largest Improvements

1. **`depends_on` reduction:** 1,931 → 525 edges. The filter eliminated the "mode star" and "timing variable" pollution.
2. **False `controls` eliminated:** `tx`, `clk`, `run`, `q0` no longer generate `controls` to actuators.
3. **Overall graph density reduced:** 6,296 → 1344 edges (21.3% remaining).

## 4. Remaining Low-Precision Sources

1. **`controls` from sensors:** `in0` → `Q0` is still `controls` because of Phase 2 `is_actuator_target`. The filter keeps `in0` as edge-worthy but does not change the relation type. Precision: 72.8%.
2. **`depends_on` fallback:** Some genuine `depends_on` edges remain (e.g., `REV_IN → _CRC_GEN`), but the filter cannot distinguish them from weak ones without deeper semantic analysis.
3. **`sequences` from R4/R5:** CASE-based `sequences` still has over-generation (1,125 edges). The filter only affects R1, not R4/R5.
4. **No `enables` coverage:** Sensor guards (`in0`, `Xi*`) that are edge-worthy still get `controls` or `depends_on`, never `enables`. This requires a future Phase B (role-based relation mapping).

## Conclusion

The R1 filter raised overall heuristic precision from **~40%** to **88.0%** and R1 precision from **~40%** to **85.8%**.

The largest gain is in `depends_on` (eliminated 1,3xx weak edges). The largest remaining weakness is `controls` for sensor→actuator paths, which requires a future semantic-role mapping (not a filter).
